# 2026-08-03 Work Log

## Summary

- Changed Online camera acquisition from continuous capture to software-triggered capture.
- Added per-stage Online sample intervals for `idle`, `neck`, `crown`, `body`, and `endcone`.
- Renamed the old waiting stage concept to `IDLE = 0`.
- Made PLC OPC UA node settings fixed in code instead of externally configurable from `cnf.ini`.
- Removed reflector elevation writing to PLC and added a cyclic `com` heartbeat value.
- Moved `PlcSettings` into the PLC communication module.

## Online Trigger Capture

- Added `online_camera_trigger_requested` in `src/modules/signals.py`.
- In Online mode, `PageCamera` now starts both cameras with:
  - trigger source: software
  - trigger mode: enabled
- `PageHome` owns an `online_trigger_timer`.
- Each timer timeout emits a software trigger request for both cameras.
- Calibration camera usage remains continuous capture, so calibration behavior is not changed.

## Stage Sample Intervals

- Added runtime interval parameters in `src/cnf.ini`:

```ini
idle_sample_interval_ms = [8000]
neck_sample_interval_ms = [300]
crown_sample_interval_ms = [1000]
body_sample_interval_ms = [1000]
endcone_sample_interval_ms = [1000]
```

- Added corresponding fields in `RuntimeSettings`.
- Added minimum interval clamping in `ConfigManager._set_runtime()`.
- `PageHome` refreshes the Online trigger interval from the current PLC stage.
- `IDLE` uses the Neck processing path, but with the longer idle sampling period.

## Measurement Stage

- Replaced `MeasurementStage.WAITING` with:

```python
MeasurementStage.IDLE = 0
```

- `MeasurementStage.from_value(0)` now returns `IDLE`.
- Unknown or invalid stage values also fall back to `IDLE`.
- `MeasurementEngine.process()` maps `IDLE` to Neck processing internally while preserving the original result stage.

## PLC Fixed Settings

- Removed `[PLC]` from `src/cnf.ini`.
- `ConfigManager` no longer loads or exposes a mutable PLC settings group.
- `PageHome` no longer checks `self.config.plc`.
- `OpcUaWorker` creates its own fixed `PlcSettings`.
- `PlcSettings` now lives in `src/measurement_core/plc.py`, together with `OpcUaGateway`.

Fixed PLC nodes:

```text
endpoint_url = opc.tcp://192.168.0.1:4840
mode_node = ns=3;s="Camera_Data_Global"."V285_Melt_Level_Mode_From_Camera"
shoulder_transition_node = ns=3;s="Camera_Data_Global"."shoulderMode"
melt_level_node = ns=3;s="Camera_Data_Global"."meltLevel"
diameter_node = ns=3;s="Camera_Data_Global"."diameter"
hr_node = ns=3;s="Camera_Data_Global"."hr"
com_node = ns=3;s="Camera_Data_Global"."com"
```

## PLC Output Changes

- Stopped writing `reflector_elevation_mm` to PLC.
- Added `com` output as a software heartbeat/counter.
- `com` increments once per PLC write cycle and wraps in the range `0..100`:

```text
0, 1, 2, ..., 100, 0, 1, ...
```

- PLC writes now include:
  - melt level
  - diameter
  - HR
  - COM counter
- Writes continue to use `set_attribute(AttributeIds.Value, DataValue)` to avoid Bozhong OPC UA write errors caused by unsupported timestamp/status combinations.
