# 2026-07-15 Work Log

## Summary

- Added automatic/manual center selection for checkerboard detection.
- Added independent camera ROI configuration and ROI visualization.
- Changed automatic center detection to locate the white ring inside the configured ROI.
- Simplified center-corner selection to the four nearest corner candidates.
- Updated `goodFeaturesToTrack` spacing to use the checkerboard square pixel size.

## Automatic And Manual Center Modes

- Added an Auto/Manual center mode toggle to the Calibration page.
- Manual mode continues to use the center selected in the camera views.
- Auto mode detects the white ring on the dark center square and uses its center as the checkerboard center.
- The automatic detector uses the threshold configured by `auto_center_threshold` in `cnf.ini`.
- Removed the percentile-based adaptive threshold, `hole_ratio` filtering, and the bright-pixel fallback detector.

## Camera ROI

- Added independent ROI parameters for camera 1 and camera 2:

```ini
camera1_roi_x
camera1_roi_y
camera1_roi_width
camera1_roi_height
camera2_roi_x
camera2_roi_y
camera2_roi_width
camera2_roi_height
```

- `_auto_center_from_ring()` searches only inside the corresponding camera ROI.
- The ROI is drawn as a green rectangle in each camera view.
- The average grayscale value inside the ROI is shown in large green text at the ROI's upper-left corner.
- ROI coordinates are clipped to the current image bounds; a non-positive ROI width or height falls back to the full image.

## Center Corner Detection

- `goodFeaturesToTrack()` now receives the camera ROI through its `mask` argument.
- `_center_four_from_seed()` no longer crops or recalculates a separate ROI.
- After the center is known, the four candidates nearest to the center are selected and ordered as the center four corners.
- Candidate points are no longer drawn in the preview.
- Only the selected `center_four` points are highlighted with large green star markers.

## Square Size Parameter

- Changed the meaning of `manual_center_radius_px`: it now represents the approximate pixel side length of one checkerboard square.
- `goodFeaturesToTrack()` uses:

```python
minDistance = max(4, round(square_size_px * 0.7))
```

- This spacing suppresses multiple feature points from the same checkerboard corner neighborhood while retaining adjacent checkerboard corners.
- Preserved the manually adjusted `goodFeaturesToTrack()` parameters in the actual project file:

```python
maxCorners=100
qualityLevel=0.1
blockSize=11
useHarrisDetector=False
```
