旧版同机对比基线为提交 6ce660c44a9158c8d7e5d99e144c7250822eee12。其源码独立恢复至 out/baseline-refactor-20261004，仅增加基准入口，不修改业务源码；PVA_LEGACY_UI_BENCHMARK 使用旧 PageHome 的启动入口和成功测量状态通知计数。当前版本统计结果完成信号，本组 Neck 输入可正常测量。

两版在本组合成图上均达到 50 ms 目标，不能据此认定旧版在现场没有卡顿。重构后 P95 降低，但末次工作集略高（约 57 MiB 对 54 MiB）；本次主要收益是职责解耦、减少 UI 线程工作和限制队列，而不是降低所有场景的内存占用。

上述 P95 是事件循环定时器延迟的代理指标，不是实际鼠标输入到屏幕显示的延迟。工作集末值接近首值，但仅凭本测试不能证明不存在任何内存泄漏。测量不在隔离机器上进行，不能将单次差异解释为所有生产场景的加速比例。最后的相对导航和相机接管修正不改变此离线连续测量路径。

## 构建与遗留清理

- MSVC 本机仅有中文消息资源，VSLANG 无法强制英文。tools/msvc_utf8.cmd 统一代码页，CMake 探测实际 /showIncludes 前缀；已确认 Ninja 记录头文件依赖，不再混用旧目标文件。
- 修正 VS Code Release 任务大小写及 Run 对 Build 的依赖。工作区仍应打开工程根目录，而不是辅助脚本所在的 cpp 子目录。
- 删除无引用的 CameraSource；旧跨页面采集信号链已移除。全局信号仅保留状态提示和退出广播。
- 本次测试均使用临时状态目录，保留用户已有 measurement_state.json 和 plc_runtime_state.json 改动。
