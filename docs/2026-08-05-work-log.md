## OpenCV Convexity Defects Crash Fix

### Problem

- Online neck processing could fail at:

```python
defects = cv2.convexityDefects(contour, hull_indices)
```

- Runtime error:

```text
The convex hull indices are not monotonous, which can be in the case when the input contour contains self-intersections
```

- Root cause:
  - `cv2.convexityDefects` requires a valid ordered contour and matching hull indices.
  - Some extracted reflector or crescent contours can contain self-intersections or invalid ordering.
  - The previous code did not guard this OpenCV exception, so one bad contour could interrupt the measurement cycle.

### Changes

- Updated `src/measurement_core/engine.py`.
- In `_extract_outer_convex_arc`:
  - Convert contour input to contiguous `int32` before calling OpenCV convex hull and convexity defects APIs.
  - Wrap `cv2.convexityDefects` with `try/except cv2.error`.
  - If OpenCV rejects the contour, treat it as "no usable convex defect" and return the original contour as a closed contour.
  - This keeps the existing fallback behavior and avoids breaking the online cycle.

### Test Coverage

- Updated `tests/test_measurement_core.py`.
- Added a regression test that simulates `cv2.convexityDefects` throwing `cv2.error`.
- Verified `_extract_outer_convex_arc` returns the original contour instead of propagating the exception.
